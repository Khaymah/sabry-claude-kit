# File uploads

- **Situation:** avatars, product images, documents (PDF, ID scans), attachments, "upload a file", serving uploaded files, private documents, image resizing.
- **Skip when:** files are only generated by us and never uploaded (still read the serving rules).
- **Decision:** uploads go straight to object storage (S3-compatible: Cloudflare R2, DigitalOcean Spaces, Wasabi, MinIO on a VPS) through short-lived presigned URLs, or are streamed to disk on the VPS with hard limits. Files get random names, a metadata row, a type checked by content, and are private by default, served through signed URLs or Nginx with an auth check.

## Levels

| Level | Pick when |
|---|---|
| Minimum | Small files on one VPS: streamed to a directory outside the web root |
| Standard | Production: object storage with presigned uploads, processing jobs |
| Advanced | Sensitive documents: malware scanning, encryption at rest per tenant, retention rules |

## Rules

### Minimum — always, never cut

- Size limit per route (Nginx `client_max_body_size` in that `location`, plus the app check), and a type allow-list per purpose (`image/jpeg`, `image/png`, `image/webp` for avatars).
- Type checked from the file's bytes (`file-type`), not from the extension or the client's `Content-Type`.
- Stored under a generated name (`<uuidv7>.<ext from detected type>`), never the user's filename in a path; the original name kept only in the metadata row, sanitised for display.
- Upload directory outside the web root; Nginx never executes or interprets anything from it; served with `Content-Disposition` and `X-Content-Type-Options: nosniff`.
- A `Files` row per upload: `Id`, `OwnerId`, `TenantId`, `Purpose`, `StorageKey`, `MimeType`, `SizeBytes`, `OriginalName`, `Status`.

### Standard — adds

- Object storage with presigned `PUT` (5–10 min, exact content type and max length in the policy); the client uploads directly, then calls `POST /files/:Id/complete`; the server verifies size and type with a `HEAD`/range read before marking it `Ready`.
- Private bucket; downloads by presigned `GET` (minutes) after the permission check, or through the app for strictly private files.
- Images processed in a job (`sharp`): EXIF stripped (location data), resized variants, WebP/AVIF; the original kept only if needed.
- Orphan cleanup: `Pending` files older than a day and files of deleted records removed by a job.
- Storage credentials and bucket names in `SystemSettings`.

### Advanced — adds

- Malware scanning (ClamAV) in a job before a document is `Ready`; infected files quarantined.
- Per-tenant prefixes and lifecycle rules; encryption keys per tenant where required.
- CDN in front of public images with signed URLs or tokens for private ones.

## Edge cases

| Case | Expected behaviour |
|---|---|
| `photo.jpg` that is really an HTML or SVG file | Rejected: detected type not in the allow-list (SVG never accepted for user uploads unless sanitised) |
| Client uploads but never calls `complete` | File stays `Pending` and the cleanup job deletes it |
| 2 GB upload on a slow mobile network | Multipart upload to storage with resumable parts; the API only issues part URLs |
| Arabic filename `صورة البطاقة.pdf` | Stored under a UUID; original name returned in `Content-Disposition` with RFC 5987 encoding |
| User replaces their avatar | New file `Ready` first, then the old one deleted by a job; no broken image in between |
| 100×: millions of files | Keys prefixed by tenant and date; listings come from the `Files` table, never from bucket listing |
| Twice / parallel: the same `complete` called twice | Conditional update from `Pending` to `Ready`; the second is a no-op |

## Example — Standard, Bun + S3-compatible storage

```ts
import { S3Client, PutObjectCommand } from "@aws-sdk/client-s3"
import { getSignedUrl } from "@aws-sdk/s3-request-presigner"

const AVATAR = { Types: ["image/jpeg", "image/png", "image/webp"], MaxBytes: 5 * 1024 * 1024 }

export async function StartAvatarUpload(UserId: string, Body: { ContentType: string; SizeBytes: number; Name: string }) {
  if (!AVATAR.Types.includes(Body.ContentType) || Body.SizeBytes > AVATAR.MaxBytes) throw new AppError("FILE_NOT_ALLOWED", 400)
  const Id = uuidv7()
  const Key = `avatars/${UserId}/${Id}`
  await db.insert(Files).values({ Id, OwnerId: UserId, Purpose: "Avatar", StorageKey: Key, MimeType: Body.ContentType, SizeBytes: Body.SizeBytes, OriginalName: Body.Name.slice(0, 200), Status: "Pending" })
  const Url = await getSignedUrl(Storage(), new PutObjectCommand({ Bucket: GetSetting("Storage.Bucket"), Key, ContentType: Body.ContentType, ContentLength: Body.SizeBytes }), { expiresIn: 600 })
  return { FileId: Id, UploadUrl: Url }
}

export async function CompleteUpload(UserId: string, FileId: string) {
  const Head = await ReadFirstBytes(FileId, UserId, 4100)
  const Detected = await fileTypeFromBuffer(Head.Bytes)
  if (!Detected || !AVATAR.Types.includes(Detected.mime) || Head.Size > AVATAR.MaxBytes) {
    await DeleteStoredFile(FileId)
    throw new AppError("FILE_NOT_ALLOWED", 400)
  }
  const [Done] = await db.update(Files).set({ Status: "Ready", MimeType: Detected.mime })
    .where(and(eq(Files.Id, FileId), eq(Files.OwnerId, UserId), eq(Files.Status, "Pending")))
    .returning({ Id: Files.Id })
  if (Done) await Boss.send("Files.ProcessImage", { FileId })
}
```

`ReadFirstBytes` does a ranged `GetObject` (`Range: bytes=0-4099`) and a `HeadObject` for the real size, scoped to the owner's file row.

## Verify

- [ ] `[M]` An HTML file renamed to `.jpg` is rejected.
- [ ] `[M]` A file over the limit is rejected by Nginx or the app, never written fully.
- [ ] `[M]` Stored names are UUIDs; no user input in paths (`../` test).
- [ ] `[S]` A private file URL from another user returns 404; presigned URLs expire.
- [ ] `[S]` Uploaded JPEGs have no GPS EXIF after processing.
- [ ] `[A]` The EICAR test file is quarantined.

## Pitfalls

- **Trusting the extension or `Content-Type`** → stored XSS and malware → magic bytes.
- **Public bucket by default** → ID scans indexed by search engines → private + signed URLs.
- **Buffering uploads in memory** → OOM on big files → direct-to-storage or streaming.
